# Semantic Library

## Meaning model

Every scene must carry three visible facts and may carry one subtle continuation cue:

| Fact | Visual evidence |
| --- | --- |
| Retrieval and evaluation completed | orderly retrieved documents; closed evaluation ring; aligned pipeline; small restrained completion marker |
| Valid statistics are sparse | two or three tokens; widely spaced nodes; mostly unused slots; near-empty chart without zero labels |
| No negative conclusion follows | intact equipment; calm blue palette; stable upright composition; no alarm conventions |
| Re-evaluate later | quiet clock, cycle ring, calendar tabs, or forward orbit |

## Business objects

- Application behavior: application form silhouettes, inbox slots, bank/non-bank building tokens.
- Consumer drawdown: card plus a small number of settled transaction slips; avoid cash piles.
- Installment amount or count: segmented cycle ring with only two or three occupied segments.
- Limit distribution: stacked limit cards or a measuring gauge with sparse data tokens; never show a red low gauge.
- Performance: schedule ring with a few completed checkpoints; do not use overdue badges.
- Institution-count change: orderly bank/building tokens placed on a timeline with wide gaps.
- Bank/non-bank distribution: two neutral institution trays with sparse tokens; do not visually rank one as dangerous.
- Special-period behavior: calendar or clock band with a quiet highlighted interval and very few events.

## Report and model objects

- Report folder, document stack, clipboard without writing, blank chart plane, data pipeline, evaluation ring, model core, analytical lens, or statistical pedestal.
- A blank report surface may have geometric chart axes or two dots, but no digits, words, currency signs, or pseudo-text lines that resemble writing.
- Use the model object as evidence of completed analysis, not as a robot character.

## Recommended combinations

- Report folder + aligned evaluated sheets + two data tiles + cycle cue.
- Closed model ring + two input spheres + clear result plane + subtle forward orbit.
- Installment cycle + two occupied segments + report tile + small completion bead.
- Bank/institution pedestal + two application tokens + sparse dot chart + time ring.

## Concrete scene patterns

- Consumer-demand application: emphasize a recognizable consumption moment—retail display, household product, shopping bag, consumer-service kiosk, or blank application card. A person may submit or compare, but avoid reusing a generic analysis wall.
- Application count and timing: emphasize a calendar, clock, seasonal strip, or ordered time shelf with two widely separated application artifacts. The scene can work without a person; a small evaluated report seal or settled document stack may imply completed analysis.
- Bank-institution distribution: make bank architecture, branch counters, institution folders, or a geographic branch arrangement the largest visual mass. A person is optional and must not obscure the bank focus. Use one or two application artifacts among several neutral institutions.

When a character appears, the action must make the business dimension concrete. Sparse records are evidence of limited behavior, never a failed request or inaccessible source.

For sets, choose different dominant object families and silhouettes for every image. Do not repeat the same terminal, pipeline, tray, check badge, or character pose across scenes.

## Scene-logic gate

Draft each image as `place -> actor/action -> business object -> observable result`.

- Place must be recognizable from architecture or task furniture, not inferred from a floating icon.
- The action must be physically plausible: hands touch or hold the relevant object, gaze follows the task, and nearby surfaces support that action.
- The sparse result must appear on the same object, counter, calendar, or institution arrangement affected by the action.
- Supporting objects must share one workflow. Delete any prop that belongs to a different everyday activity or exists only to fill space.
- Abstract geometry is allowed only when attached to a concrete subject: a time arc around calendars, an observation node on a branch map, or a completion light on a report device.

## Dangerous readings to prevent

- An empty box alone reads as missing or not delivered.
- A magnifier over nothing can read as search failure unless completed documents are also present.
- A broken or incomplete ring can read as processing still underway; show a completed evaluation loop and use a separate future-monitoring orbit.
- A downward chart implies deterioration; use sparse neutral points rather than decline.
- A shield, lock, warning triangle, red accent, cross, or exclamation mark implies security, access, or risk.
- A checkmark by itself implies generic success; pair it with sparse evidence and a reporting object.
